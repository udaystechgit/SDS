# Architecture

## Overview

SDS AI Core is a **full-stack SSR application** built on [TanStack Start](https://tanstack.com/start). It runs a single Vite-powered codebase that produces both a client bundle and a server bundle, enabling server-side rendering with client-side hydration.

---

## Rendering Model

```
Browser Request
      │
      ▼
  SSR Server (.output/server/)
      │  renders React tree → HTML string
      ▼
  HTML sent to browser
      │
      ▼
  Client bundle (.output/public/) hydrates the page
      │
      ▼
  TanStack Router takes over for SPA-style navigation
```

- **Entry point**: `src/start.ts` wires TanStack Start middleware and the generated route tree.
- **Router**: `src/router.tsx` — single router instance shared between server and client
- **Route tree**: `src/routeTree.gen.ts` — auto-generated by the TanStack Router Vite plugin. **Never edit this file manually.**

---

## Build Output

| Path              | Contents                                |
| ----------------- | --------------------------------------- |
| `.output/public/` | Static assets + hydration JS/CSS chunks |
| `.output/server/` | Node-compatible server bundle           |

Run `npm run build` to produce both.

## Data Flow

### Server Functions (`src/lib/api/`)

Server-only logic is co-located with the routes via **server functions** (`createServerFn`). These functions:

- Run exclusively on the server
- Are called from route loaders or component event handlers
- Never ship to the browser bundle

```ts
// Example pattern
import { createServerFn } from "@tanstack/react-start";

export const myServerFn = createServerFn().handler(async () => {
  // safe to use server-only modules here
  return data;
});
```

### Client Config vs. Server Config

| File                       | When to use                                                                                         |
| -------------------------- | --------------------------------------------------------------------------------------------------- |
| `src/lib/config.server.ts` | Server-only secrets (DB URL, API keys). Reads `process.env` inside a function, not at module scope. |
| `import.meta.env.VITE_*`   | Public values safe to expose in the browser (analytics IDs, public API URLs).                       |

## Key Libraries

| Library                       | Role                                               |
| ----------------------------- | -------------------------------------------------- |
| `@tanstack/react-router`      | File-based routing, type-safe links, search params |
| `@tanstack/react-start`       | SSR adapter, server functions, streaming           |
| `@tanstack/react-query`       | Async state management for server-fetched data     |
| `@hookform/resolvers` + `zod` | Form validation                                    |
| `tailwindcss` v4              | Utility-first styling                              |
| `shadcn/ui` primitives        | Accessible component base layer (Radix UI)         |
| `@supabase/supabase-js`       | Database and auth-aware backend access             |

## SEO

Page `<head>` metadata is managed via the `head()` export on each route:

```ts
export const Route = createFileRoute("/about")({
  head: () => ({
    meta: buildSeoMeta({
      title: "About SDS | ...",
      description: "...",
      path: "/about",
    }),
  }),
  component: AboutPage,
});
```

The `buildSeoMeta()` helper lives in `src/lib/seo.ts` and injects standard and Open Graph meta tags.

## Error Handling

- `src/lib/error-page.ts` — renders a friendly fallback UI
- `src/lib/lovable-error-reporting.ts` — error reporting integration

## Styling Conventions

- Tailwind CSS utility classes only — no CSS Modules or styled-components
- Component variants use `class-variance-authority` (CVA) via `src/lib/utils.ts`
- Global base styles live in `src/styles.css`
